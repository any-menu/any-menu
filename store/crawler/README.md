## 社区插件爬虫系统 (不会审查)

## 背景需求

你帮我写一个github仓库，其工作流固定每日4点自动执行一次 (后期可能会改成一日多次)。工作流会执行/调用脚本执行以下工作：

- 自动搜索 github 中的带 any-menu 标签的项目
- (可选: 增量搜索, 旧项的失效检查)
- (可选: 预留一个函数，用于手动更新某个仓库。例如某个仓库已失效，或某个仓库增加了，则可以在非自动更新时间马上更新这个仓库。场景：该功能用于手动快速更新和删除仓库)
- (可选：黑名单某些满足条件的项目。场景：某些项目有木马，或误识别，则手动拉黑)
- 更新时把这些项目自动更新到 community-plugins.json。然后客户端们就可以直接访问该文件来获取社区插件列表了。
- (可选) 更新和缓存时把插件描述 (github仓库描述) 也一起存起来，star 数也可以一起更新起来。

(可选) 你可以帮我检查这套流程是否是合理的设计，有无疏漏和可改进点。用 js 还是 py 语言写会比较好。
(暂时不做，但预留追加该功能的空间) 后期可能会定期扫描是否有带毒的社区插件并预警管理人员，查看是否将其归入黑名单。

(其他疑问) obsidian 的社区插件注释是如何做到，当你的插件更新、表单文件变化后，他会马上知道并在插件市场预览时直接显示最新的版本号。

可选参考的一些例子：
- Obsidian 插件（分官方上架版（可从官方仓库清单文件json中看到）、未上架版（可从issue中看到），还有一个是 github 上所有的 Obsidian 版本，我目前主要关注第三项）
- 机器人社区插件
- ComfyUI 社区插件
- 其他补充……
